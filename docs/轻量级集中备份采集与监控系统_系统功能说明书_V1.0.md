## 2. 系统定位

本系统是一套面向中小型企业 Windows 服务器环境的轻量级应用备份集中采集平台。

本系统不直接执行用友 ERP、SQL Server、OA、MES 等业务系统自身的数据备份，而是对这些应用已经自动生成的备份文件进行统一管理，完成：

1. 发现备份；
2. 判断备份是否完整；
3. 识别最新有效备份；
4. 上报备份状态；
5. 人工或自动批准上传；
6. 客户端主动上传；
7. 服务端重新校验；
8. 原始文件归档；
9. 版本保留；
10. 异常告警；
11. 备份查询与恢复取回；
12. 操作审计。

系统核心价值是：

> 在不改变现有业务系统备份方式的前提下，将分散、依赖人工的备份文件复制工作，改造成集中、可追踪、可校验、可恢复的标准化流程。

## 4. 术语定义

| 术语 | 定义 |
|---|---|
| 客户端 | 安装在业务服务器上的 Windows Agent |
| 服务端 | 集中管理客户端、接收文件并保存备份的系统 |
| 备份任务 | 对一个应用备份目录及其识别、上传、保留规则的完整配置 |
| 业务单元 | 任务下的独立备份对象，例如用友账套、数据库实例、部门 |
| 候选备份集 | 客户端识别出的可能属于最新一份备份的文件或目录集合 |
| 预检 | 对候选备份集进行稳定性、完整性、时间、容量和必需文件检查 |
| 正式入库 | 文件上传完成并经服务端校验后进入正式仓库 |
| 上传会话 | 一次备份集上传过程的上下文 |
| 清单 | 描述备份集文件、路径、大小、时间和哈希的 manifest |
| 手动模式 | 客户端不自动上传，等待管理员下发命令 |
| 人工确认模式 | 客户端自动扫描与预检，管理员确认后上传 |
| 自动模式 | 预检通过后在规定时间自动上传 |
| 仅监控模式 | 只检测备份是否生成，不上传 |
| 暂停模式 | 不扫描、不预检、不上传 |

## 7. 客户端功能

### 7.1 客户端安装

客户端安装包应支持静默安装和图形化安装。

安装时需要：

- 选择安装目录；
- 填写服务端地址；
- 填写一次性注册令牌；
- 设置客户端显示名称；
- 测试服务端连通性；
- 注册 Windows Service；
- 设置服务自动启动；
- 设置服务异常自动恢复；
- 初始化本地状态库和日志目录。

安装完成后，不提供常驻桌面程序。

**验收要求：**

- Windows Server 2012 R2、2016、2019、2022 能正常安装；
- 重启系统后 Agent 自动启动；
- 安装失败时有明确日志；
- 卸载时默认保留本地状态和日志，可由管理员选择清理。

### 7.2 客户端注册

客户端首次启动后，使用一次性注册令牌向服务端申请注册。

注册信息包括：

- 机器唯一标识；
- 计算机名称；
- 操作系统版本；
- Agent 版本；
- IP 地址；
- 本机生成的公钥；
- 客户端显示名称；
- 注册时间。

服务端可以配置：

- 自动审批；
- 人工审批；
- 令牌绑定客户端分组；
- 令牌失效时间；
- 令牌最大使用次数。

客户端注册成功后获得独立客户端证书或身份凭据。

**安全要求：**

- 每台客户端身份独立；
- 注册令牌只能短期有效；
- 注册令牌不能作为长期认证凭据；
- 客户端被注销后，原证书立即失效；
- 证书私钥不得明文保存。

### 7.3 心跳

默认每 60 秒发送一次心跳。

心跳内容包括：

- 客户端 ID；
- 服务状态；
- 当前时间；
- 最后启动时间；
- Agent 版本；
- 配置版本；
- 当前任务数量；
- 当前执行状态；
- CPU 使用率；
- 内存使用率；
- 磁盘剩余空间；
- Agent 进程资源；
- 关键服务状态；
- 待上传任务数；
- 当前上传速度。

心跳同时承担：

- 检查配置版本；
- 领取服务端指令；
- 上报未发送事件；
- 上报上传进度；
- 更新在线状态。

**在线状态判定：**

- 2 个心跳周期内收到：在线；
- 超过 3 个周期未收到：疑似离线；
- 超过 5 分钟未收到：离线；
- 客户端主动上报停止：已停止。

### 7.4 本地配置缓存

客户端必须保存最后一次有效配置。

当服务端暂时不可用时：

- Agent 继续运行；
- 保留本地已知任务；
- 自动模式是否继续执行由任务配置决定；
- 手动模式不允许离线自行上传；
- 待上报事件进入本地队列；
- 网络恢复后自动补报。

本地配置必须包含版本号和签名。

### 7.5 目录扫描

客户端根据任务配置扫描备份目录。

支持：

- 本地盘符；
- 中文路径；
- 长路径；
- 递归或非递归扫描；
- 包含规则；
- 排除规则；
- 文件扩展名；
- 通配符；
- 正则表达式；
- 最大扫描深度；
- 最大文件数量保护；
- 忽略临时文件；
- 忽略隐藏文件；
- 忽略零字节文件。

默认不支持网络共享路径。确有需要时，应单独启用并提示安全风险。

**扫描触发方式：**

- 定时扫描；
- 文件变化触发扫描；
- 服务启动后扫描；
- 管理员下发预检；
- 上传前重新扫描。

文件变化监听只能作为辅助，必须保留定期全量扫描兜底。

### 7.6 备份识别类型

#### 7.6.1 最新单文件

适用于：

- SQL Server `.bak`；
- `.zip`；
- `.7z`；
- `.rar`；
- `.db`；
- 自定义单文件。

识别条件：

- 符合包含规则；
- 不符合排除规则；
- 修改时间在允许范围内；
- 文件大小大于最小值；
- 选择修改时间最新的文件；
- 若时间相同，选择创建时间较新或文件名排序较后的文件。

#### 7.6.2 最新目录

适用于每次备份生成一个新目录的应用。

识别条件：

- 目录名称符合规则；
- 目录修改时间或目录内最新文件时间满足要求；
- 目录中至少包含指定数量文件；
- 必需文件存在；
- 目录内容在稳定期内不再变化。

#### 7.6.3 多文件备份集

同一备份批次包含多个文件。

支持按以下字段归组：

- 文件名前缀；
- 文件名日期；
- 文件名时间；
- 批次号；
- 正则表达式命名组；
- 相同父目录；
- 时间容差。

完整条件：

- 指定类型文件全部存在；
- 文件数量达到要求；
- 各文件批次标识一致；
- 各文件均通过稳定性检查。

#### 7.6.4 多子目录、多账套

根目录下每个指定层级子目录代表独立业务单元。

功能要求：

- 自动发现业务单元；
- 支持业务单元别名；
- 每个业务单元独立识别；
- 每个业务单元独立预检；
- 单个业务单元失败不影响其他业务单元；
- 支持忽略指定目录；
- 支持设置预期业务单元清单；
- 缺少预期账套时产生告警。

### 7.7 文件稳定性判断

客户端发现候选备份后，执行稳定性判断。

默认流程：

1. 记录文件数量、总大小、最大修改时间；
2. 等待稳定间隔；
3. 再次扫描；
4. 比较文件数量；
5. 比较每个文件大小；
6. 比较修改时间；
7. 尝试以只读共享方式打开；
8. 检查是否存在临时扩展名；
9. 检查必需文件；
10. 检查容量范围；
11. 生成预检结果。

默认稳定间隔为 10 分钟，可配置为 1 至 120 分钟。

状态：

- 待稳定；
- 稳定；
- 仍在变化；
- 必需文件缺失；
- 容量异常；
- 文件不可访问；
- 路径不存在；
- 超过等待时限。

### 7.8 候选备份集

预检通过后，客户端生成候选备份集。

候选备份集包含：

- 候选备份集 ID；
- 客户端 ID；
- 任务 ID；
- 业务单元 ID；
- 原始路径；
- 文件相对路径；
- 文件大小；
- 最后修改时间；
- 文件 SHA-256；
- 文件总数；
- 总容量；
- 发现时间；
- 预检时间；
- 备份业务时间；
- 完整性结论。

上传前必须再次核对：

- 路径是否仍存在；
- 文件大小是否变化；
- 修改时间是否变化；
- 文件数量是否变化；
- 快速指纹是否变化。

如发生变化，旧候选集失效，重新预检。

### 7.9 指令执行

客户端通过主动心跳领取指令。

允许指令：

- 预检任务；
- 预检全部任务；
- 上传候选备份集；
- 上传最新有效备份；
- 暂停上传；
- 继续上传；
- 取消上传；
- 重新扫描；
- 重新计算哈希；
- 同步配置；
- 刷新主机状态；
- 客户端安全升级。

每条指令必须检查：

- 指令是否发给本客户端；
- 指令是否过期；
- 指令是否已执行；
- 指令签名是否有效；
- 指令类型是否在白名单；
- 任务是否启用；
- 参数是否符合规则。

系统严禁提供任意脚本、命令行和程序执行能力。

### 7.10 分块上传

上传大文件时采用分块方式。

功能要求：

- 默认分块 8MB；
- 支持 4MB、8MB、16MB、32MB；
- 每块独立编号；
- 每块计算哈希；
- 服务端返回已接收块；
- 断线后只上传缺失块；
- 文件全部完成后计算整文件哈希；
- 支持单文件顺序上传；
- 支持任务级带宽限制；
- 支持全局并发许可。

上传前检查：

- 备份集仍有效；
- 服务端已授权；
- 服务端空间充足；
- 客户端资源符合条件；
- 当前时间在允许窗口内；
- 同任务没有其他上传实例。

### 7.11 客户端资源保护

客户端应配置资源阈值：

- CPU 持续超过阈值时暂缓；
- 内存占用超过阈值时暂缓；
- 源磁盘空间不足时告警；
- 工作时间降低带宽；
- 业务关键服务繁忙时可暂停；
- 每次只运行有限数量扫描线程；
- 每次只上传一个任务。

管理员可以对单次任务选择：

- 按规则执行；
- 忽略资源告警但继续；
- 强制执行。

### 7.12 本地日志

日志分类：

- 启动日志；
- 注册日志；
- 心跳日志；
- 配置同步日志；
- 扫描日志；
- 预检日志；
- 哈希日志；
- 上传日志；
- 指令日志；
- 错误日志；
- 安全日志。

日志要求：

- 按日期滚动；
- 单文件大小限制；
- 总容量限制；
- 默认保留 30 天；
- 敏感凭据不得写入日志；
- 支持服务端远程查看摘要；
- 完整日志下载必须经过权限控制。

- 本周正式入库数；

### 8.12 校验与正式入库

上传完成后执行：

1. 检查文件数量；
2. 检查总容量；
3. 检查相对路径；
4. 计算每个文件 SHA-256；
5. 与客户端清单比较；
6. 检查临时区文件完整；
7. 生成服务端 manifest；
8. 原子移动至正式仓库；
9. 写入备份版本记录；
10. 更新任务状态；
11. 发送成功通知。

校验失败时：

- 不进入正式仓库；
- 保留临时文件一定时间；
- 产生严重告警；
- 允许重新上传错误文件；
- 记录客户端和服务端哈希差异。

### 8.13 正式备份仓库

正式仓库按以下逻辑组织：

```text
仓库根目录/
  客户端名称/
    应用名称/
      业务单元/
        备份时间_备份集ID/
          原始备份文件
          manifest.json
```

要求：

- 路径由服务端生成；
- 客户端不能指定绝对目标路径；
- 同一备份版本不可覆盖；
- 目录创建和入库必须原子化；
- 文件保留原始名称和相对路径；
- 管理员可以直接读取原始文件；
- 正式仓库不向业务服务器共享。

## 9. 运行模式

### 9.1 自动上传模式

流程：

1. 到达扫描时间；
2. 客户端扫描；
3. 生成候选；
4. 执行稳定性判断；
5. 预检通过；
6. 到达上传窗口；
7. 客户端申请上传；
8. 服务端发放许可；
9. 上传、校验、入库。

### 9.2 人工确认模式

流程：

1. 客户端自动扫描；
2. 自动预检；
3. 服务端显示“等待人工确认”；
4. 管理员选择任务；
5. 下发上传；
6. 服务端自动排队；
7. 客户端上传；
8. 服务端校验入库。

### 9.3 完全手动模式

流程：

1. 客户端只保持心跳；
2. 管理员下发预检；
3. 客户端扫描和判断；
4. 管理员查看结果；
5. 管理员下发上传；
6. 客户端上传。

### 9.4 仅监控模式

客户端只上报：

- 是否生成新备份；
- 最新备份时间；
- 文件容量；
- 预检状态。

不上传文件。

### 9.5 暂停模式

- 不自动扫描；
- 不自动预检；
- 不自动上传；
- 仍保持心跳；
- 管理员可恢复。

## 10. 核心业务流程

### 10.1 客户端注册流程

```text
创建注册令牌
  → 安装 Agent
  → Agent 生成机器身份
  → 提交注册申请
  → 服务端审批
  → 签发客户端身份
  → Agent 保存凭据
  → 首次心跳
  → 同步任务配置
```

### 10.2 预检流程

```text
触发预检
  → 检查任务和路径
  → 扫描候选
  → 按规则归组
  → 判断备份时间
  → 第一次快照
  → 等待稳定时间
  → 第二次快照
  → 检查必需文件
  → 检查容量
  → 生成哈希和清单
  → 上报预检结果
```

### 10.3 手动批量上传流程

```text
管理员选择“本周全部预检”
  → 客户端分别预检
  → 服务端汇总结果
  → 管理员选择“上传已就绪”
  → 服务端创建批次
  → 按优先级排队
  → 客户端领取上传指令
  → 上传前二次核对
  → 申请上传会话
  → 分块上传
  → 服务端校验
  → 正式入库
  → 生成汇总结果
```

### 10.4 断点续传流程

```text
上传中断
  → 客户端保存会话 ID
  → 服务端保留已完成块
  → 网络恢复
  → 客户端查询会话
  → 服务端返回缺失块
  → 客户端继续上传
  → 完成整体校验
```

### 10.5 恢复下载流程

```text
恢复操作员查询备份
  → 选择版本
  → 填写恢复用途
  → 系统重新校验
  → 生成短期下载会话
  → 下载文件
  → 记录下载结果
```

## 12. 异常处理

### 12.1 路径不存在

- 任务状态设为路径不存在；
- 产生重要告警；
- 不自动创建源目录；
- 下次扫描继续检查。

### 12.2 文件仍在变化

- 保持等待稳定状态；
- 按配置间隔重试；
- 超过最大等待时间后告警；
- 不上传半成品。

### 12.3 备份时间过旧

- 标记本周无新备份；
- 不允许旧备份冒充本周成功；
- 可由管理员选择强制上传旧版本，但必须记录原因。

### 12.4 候选集上传前变化

- 旧候选集失效；
- 上传指令终止；
- 重新预检；
- 提示管理员“候选备份已变化”。

### 12.5 网络中断

- 保留上传会话；
- 指数退避重试；
- 超过重试次数后等待人工处理；
- 不重复上传已确认分块。

### 12.6 服务端空间不足

- 拒绝新会话；
- 已开始会话可按策略暂停；
- 产生严重告警；
- 禁止因空间不足覆盖旧备份。

### 12.7 哈希不一致

- 不正式入库；
- 标记校验失败；
- 定位到具体文件；
- 允许仅重传错误文件；
- 产生严重告警。

### 12.8 客户端时间异常

- 心跳显示时间偏差；
- 超过阈值告警；
- 识别最新备份时记录偏差；
- 调度以服务端时间为准。

## 13. 非功能要求

### 13.1 性能

- 空闲 Agent CPU 接近 0%；
- 空闲 Agent 内存建议不超过 100MB；
- 心跳请求平均响应时间不超过 2 秒；
- 管理页面常用列表 3 秒内返回；
- 支持至少 100 个客户端；
- 支持至少 1,000 个备份任务；
- 支持单文件 1TB；
- 支持单备份集 100,000 个文件；
- 默认同时上传 2 个客户端；
- 支持配置最大并发。

### 13.2 可用性

- Agent 和 Server 均以系统服务运行；

## 16. 验收用例

### 16.1 单文件备份

- 目录内存在多个 `.bak`；
- 系统识别最新文件；
- 文件仍写入时不上传；
- 文件稳定后预检通过；
- 上传后双端哈希一致。

### 16.2 多文件备份集

- 同批次三个必需文件齐全；
- 系统归为同一备份集；
- 缺一个文件时预检失败；
- 补齐后重新预检成功。

### 16.3 用友多账套

- 根目录存在多个账套；
- 每个账套分别识别；
- 一个账套无新备份时单独告警；
- 其他账套仍能正常上传。

### 16.4 人工模式

- 自动上传关闭；
- 客户端保持心跳和预检；
- 管理员批量下发；
- 服务端按并发排队；
- 客户端主动上传。

### 16.5 断点续传

- 上传中断；
- 网络恢复；
- 继续上传缺失块；
- 已上传块不重复发送。

### 16.6 安全

- 非法客户端无法注册；
- 已注销客户端无法上传；
- 客户端不能指定任意目标目录；
- 重复指令不重复执行；
- 客户端不能删除旧备份；
- 普通用户不能下载无权限数据。

## 18. 总结

系统功能设计坚持以下原则：

- 不改变业务应用现有备份方式；
- 不让服务端远程进入业务服务器；
- 不使用所有服务器可写的公共共享；
- 不上传仍在生成的文件；
- 不把旧备份误判为本周成功；
- 不让客户端覆盖或删除历史备份；
- 不用复杂专用格式锁定备份；
- 不发展成大型监控或远程运维平台；
- 每次备份都必须可证明、可查询、可恢复。

系统推荐的日常运行方式是：

> 自动扫描、自动预检、管理员每周批量确认、服务端自动排队、客户端主动上传、服务端校验后正式入库。
