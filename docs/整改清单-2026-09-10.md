## 第一批：小改，堵大洞

### [x] R0 — 漏备份巡检不翻旧账

- [x] `MissedBackupWorker` 新增 `ServerStartedAtUtc`，构造时取当前时刻
- [x] cron 分支与计划分支各加守卫：`deadline < ServerStartedAtUtc` 时跳过本轮判定
- [x] 跳过数量记 info 日志，不做静默跳过
- [x] 告警正文的「已经过去 N」改为真实时长（新增 `FormatDelay`），不再印宽限期配置值
- [x] 回归测试 `服务端启动前的计划时刻不在开机第一轮里报漏备份`
- [x] 已有两处测试构造 worker 补 `ServerStartedAtUtc = UtcNow.AddDays(-365)`

**验收**：同一份数据，不推启动时刻 → 不报；推到过去 → 照报，且正文里是真实时长。

### [ ] R1 — PostgreSQL 加崩溃恢复动作（A2）

- [ ] `PostgreSqlManager.EnsureServiceRegistrationAsync` 在 `pg_ctl register` 之后补
      `sc failure BackupMonitor.PostgreSQL reset= 86400 actions= restart/5000/restart/15000/restart/60000`
      与 `sc failureflag ... 1`，与 Server / Agent 同口径
- [ ] 升级路径也要补：已存在的服务（老装机）在「修复 / 升级安装」时同样打上恢复动作
- [ ] 服务管理台的「运行诊断」里显示两个服务各自的恢复动作配置，便于现场确认

**验收**：`sc qfailure BackupMonitor.PostgreSQL` 能看到三档重启；
手工 `taskkill` postgres 进程后能自行拉起。

### [ ] R2 — 仓库 / 暂存盘不可达要报警（A3）

- [ ] `SystemWatchdogWorker.RunStorageSelfCheckAsync`：根目录解析失败时
      `RaiseAsync` 一条 Critical（`server_storage_unavailable`），不再只 `LogWarning` + `return`
- [ ] `drive.IsReady == false` 同样报警，不再 `continue`
- [ ] 恢复正常时 `RecoverAsync`，与现有 `server_storage_low` 用**不同的 alert_key**
      （「盘没了」和「盘快满了」是两件事，不能互相覆盖）
- [ ] 测试：路径不存在 / 盘未就绪两种情形各一条

**验收**：把仓库路径改成一个不存在的盘符，一轮巡检内出现告警；改回来后自动恢复。

### [ ] R3 — 按钮跟随服务状态（B5）

- [ ] `RefreshServiceStatus` 拿到的 `serverRunning` / postgres 状态传给按钮启用逻辑
- [ ] 运行中：禁用「启动服务」；已停止：禁用「停止服务」「重启服务」「打开管理网页」
- [ ] 状态读取失败时保持全部可用（读不到状态不该把出路一起藏起来，
      与托盘 `catch` 分支同一条原则）
- [ ] 忙碌态优先级高于状态态：`SetBusy(true)` 期间一律禁用

**验收**：服务运行中「启动服务」置灰；停止后「停止服务」置灰、「启动服务」恢复。

## 第二批：这套系统自己的备份

### [ ] R4 — 配置备份包自动化（A1）

设计要点先定，再动手：

- [ ] **导出到哪**：默认落到数据目录外的独立路径（同盘等于没备份），
      允许配置 UNC 路径；路径不可写时告警
- [ ] **留几份**：按份数 + 天数双限，与保留策略同风格
- [ ] **多久一次**：默认每天一次，可配；与备份计划共用时区
- [ ] 新增 API 端点：手动触发导出 / 查询上次导出时间与结果 / 下载最近一份
      （下载要走与恢复相同的一次性令牌，包里有 CA 私钥）
- [ ] 新增 worker：按计划导出，复用 `scheduled_locks` 单实例锁
- [ ] 新增告警 `config_backup_overdue`：超过 N 天没有成功导出 → Critical
- [ ] 概览页显示「上次配置备份：X 天前」，从没导出过时显著提示
- [ ] 文档：把「这个包丢了会怎样」写进部署说明

**验收**：全新装完 N+1 天，在没有任何人工操作的前提下，
指定路径里出现可用的 `.bmbp`，且概览页显示上次导出时间。

## 第三批：让人看得见

### [ ] R5 — 未配通知渠道的常驻提示（B1）

- [ ] `/admin/notifications` 配置为空时，概览页顶部常驻横幅（不是一次性 toast），
      文案说清后果：「当前没有任何通知渠道，告警只会出现在本页面」
- [ ] 横幅可跳转到通知配置页，但**不可关闭**（关掉就等于回到静默）
- [ ] 三个渠道全部 `Enabled = false` 时同样算未配置

### [ ] R6 — 服务端托盘程序（B4）

- [ ] 新建 `BackupMonitor.Server.Tray`，轮询 `/health`、`/health/db` 与两个 Windows 服务状态
- [ ] 图标三态：全绿 / 降级（服务在跑但 `/health/db` 不通）/ 红（任一服务停止）
- [ ] 菜单：打开管理网页、打开服务管理台、查看服务端指纹、启动 / 停止服务
- [ ] 状态转差时气泡通知一次（不刷屏）
- [ ] 自启：装机时注册，且要对所有登录用户生效（与 R13 同一处理）
- [ ] 服务管理台与托盘的关系：管理台不再是唯一入口，关掉窗口托盘仍在

### [ ] R7 — 客户端托盘反映真实状态（B3）

- [ ] `TrayApplicationContext` 读 Agent 数据目录下的 `state.json`
- [ ] 绿灯判据从「服务在跑」改为「服务在跑 **且** 最近一次心跳成功 **且** 无 LastError」
- [ ] 中间态（服务在跑但连不上服务端 / 证书被拒 / 未通过审批）用橙色并在
      tooltip 里写明原因
- [ ] 菜单里显示「上次成功备份：…」

### [ ] R8 — 每日摘要推送（B2）

- [ ] 新增 worker：按配置时刻汇总昨日执行情况（成功 / 失败 / 未按计划 / 离线机器数）
- [ ] 复用 `notification_deliveries` 通道，不另起投递链路
- [ ] 「一切正常」也要发——日报的意义是证明系统还活着
- [ ] 与静默规则的关系：日报不受静默影响
