## 第六批：备份的可用性与核对口径

前五批解决的是「出事了有没有人知道」。这一批解决的是另一个问题：
**入库前的哈希核对证明了「仓库里的字节 = 客户端当时的字节」，
但没有任何一处证明「这个文件能用」。**

### ~~R14 — 入库时按文件类型做结构快检~~（A4）—— 2026-09-10 决定不做

原方案：在 `UploadCommitWorker` 整份算哈希那一步顺带检查 `.bak` 文件头 / 压缩包完整性 /
0 字节与尾部截断，抓「哈希对得上但文件根本打不开」的坏备份。

**不做的理由**：`.bak` 的结构判定要靠现场真实样本才敢写，而 R16 的历史基线大小告警
已经覆盖了同一类信号里最有价值的那部分——「备份跑了但是空的 / 只剩十分之一」。
剩下的收益不足以支撑这份实现和误报风险。

**残留风险**（决定如此，记录备查）：一份哈希完整但内容损坏的备份，
系统仍然会绿灯保存并长期守护，直到真要恢复那天才发现打不开。

## 第八批：客户端升级下发（R20）

### [ ] R20 — 升级下发只暂存不生效（2026-09-11 新增，A 级）

**现象**：管理页面「客户端 → 升级」能选机器、填版本 / URL / SHA-256 并下发，
Agent 也确实执行了——但只执行了前半截。

`AgentWorker.StageUpgradeAsync`（src/agent/BackupMonitor.Agent/AgentWorker.cs:2317）做的事：
校验 URL 必须在本机的服务端上 → 下载 → 校验 SHA-256 → 解压到数据目录下的
`updates/<版本>/` → 写 `pending-update.json` → **回报 `UPGRADE_STAGED` 成功，
文案是「升级包已安全解压，将在受控重启时切换」**。

**然后没有然后了。** 全仓库 grep：`pending-update.json` 只有这一处写入，
**零个读取方**。Agent 的 Program.cs、install-agent.ps1、AgentInstaller、托盘——
没有任何一处应用这个暂存包，`updates/<版本>/` 只会越堆越多。

**为什么是 A 级**：界面显示下发成功、指令回报成功、实际运行的程序一个字节没变。
管理员据此认为全网已升级，真相要到出问题那天才暴露——与 A1、A4 同一族：
**平时完全看不出来，需要用的那天才发现没用。**

#### 第一步：止损（十分钟，即使后面的没做完也必须先做）

- [ ] 把回报文案改成实话：「升级包已下载并校验，**需要人工到这台机器上完成安装**」，
      结果码从 `UPGRADE_STAGED` 换成能看出「没装上」的值。
      不能留着一句假成功。

#### 第二步：做成真正能用的

绕不过去的限制：**Windows 服务不能替换自己正在运行的程序文件**——
进程活着时它的 exe 和已加载的 dll 都被锁住。而 Agent 是自包含发布，一个包 502 个文件。
所以必须有一个住在被替换范围**之外**的第三方来做这次交换。

- [ ] 新建 `BackupMonitor.Agent.Updater`：独立小工程，装在安装目录的同级子目录，
      **不在升级包的覆盖范围内**，否则它自己也会被锁
- [ ] Agent 侧加「空闲判定」——这就是那句注释里的**受控**：
      没有扫描 / 预检在跑、没有上传会话在传、不在备份计划的执行窗口内。
      不空闲就推迟到下一个空闲点，不要一刀切下去让传了一半的备份作废
- [ ] updater 流程：停服务 → 确认真的停了 → **备份当前目录** → 覆盖新文件 →
      启动服务 → 等心跳恢复并确认新版本号 → 删除备份
- [ ] **回滚是命门**：任一步失败立刻回滚旧目录并重新启动服务。
      升级失败 = Agent 起不来 = 这台机器再也收不到任何指令，**包括修复指令**——
      它连不上，你就没法远程救它，只能上门。回滚路径要简单到不可能出错
- [ ] 托盘一起换：它是登录用户会话里的另一个进程，跟服务不是一回事
- [ ] **分批下发（金丝雀）**：先 1 台，等它心跳恢复且版本号变了，再放 5 台，再铺开。
      一个坏包同时推给 29 台就是 29 次上门。界面上要能看到每一批的结果
- [ ] 新 Agent 起来后主动上报「升级完成 + 新版本号」，服务端据此判成功，
      而不是拿「指令执行完了」当成功
- [ ] 下发表单自动填充：服务端已经通过 `AgentVersionService` 读
      `wwwroot/downloads/agent-version.txt` 知道随附版本（R11 用的就是它）；
      再让 build-turnkey.ps1 顺手写一份 zip 的 SHA-256，
      表单里的版本 / URL / 哈希三项就不必人工敲——**手抄 64 位哈希本身就是个故障源**

**验收**：在管理页面选 1 台客户端下发升级，无需上门，该机器在数分钟内自动完成切换、
心跳恢复、上报的版本号变成新版本；人为投一个坏包，该机器能回滚并恢复心跳，不掉线。

**不要做**：不要为了省事让 Agent 自己 kill 自己再靠 SCM 拉起——
SCM 拉起的还是旧文件，而且这条路上没有任何回滚余地。
