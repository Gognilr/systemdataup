# 管理控制台 UI 重构方案

对象：[wwwroot/index.html](../src/src/BackupMonitor.Api/wwwroot/index.html)（1328 行，84 行 CSS + 1200 行原生 JS，零构建）

---

## 1. 先澄清：现在的「AI 味」不在你以为的地方

先给现状一个公道的评价：**这不是常见的那种 AI 生成 UI。** 全文件只有 1 处渐变（还是在登录页），0 处 `backdrop-filter`，没有大圆角泡泡，没有 emoji 图标，没有居中大标题配彩色光晕。信息密度也不低，表格、分页、模态、Toast、乐观锁提示都实现得很规整。写这个界面的人是懂后台系统的。

所以泛泛地说"加点毛玻璃、换个渐变"只会让它更糟。真正的 AI 味来自下面十处，全部可定位：

| # | 位置 | 症状 | 为什么这是"AI 味" |
| --- | --- | --- | --- |
| 1 | [L10–12](../src/src/BackupMonitor.Api/wwwroot/index.html:10) | `#2563eb` `#f1f5f9` `#1e293b` `#16a34a` `#d97706` `#dc2626` | **最强信号。** 这是 Tailwind 默认色板原封不动搬过来：blue-600 / slate-100 / slate-800 / green-600 / amber-600 / red-600。它是所有语言模型的默认输出，等于没做颜色决策 |
| 2 | [L37](../src/src/BackupMonitor.Api/wwwroot/index.html:37)、[L46](../src/src/BackupMonitor.Api/wwwroot/index.html:46) | 200px 深色侧栏 + 白色顶栏 + 浅灰画布 | 通用「后台模板」骨架，与业务无关，换成任何 CRUD 系统都成立 |

## 2. 但真正的问题比视觉严重得多

**信息架构复刻了 REST API，而不是运维员的工作。**

一个备份管理员坐下来，脑子里是四个问题：

1. 昨晚该跑的备份都跑了吗？
2. 哪些客户端失联了？
3. 有什么在等我审批？
4. 出事了我能不能把 X 恢复出来？

现在的控制台回答的是另一个问题：**「系统里各类对象各有多少个」**。这是库存视图，不是运维视图。

差距最刺眼的是第 1 问——**现有 UI 完全无法回答它**。仪表盘上那张 14 天柱状图只给出"全系统每天入库了几个备份集"，一根柱子高不代表该跑的都跑了：可能是同一个任务跑了 14 次，而另外 30 个任务一次没跑。要查"某个任务昨晚跑没跑"，得进备份任务列表 → 找到任务 → 点进去 → 翻备份集。四次跳转回答一个每天都要问的问题。

同样地，「待审批客户端」这个明确的待办事项，现在藏在客户端列表的行内按钮里，你得先想到去那儿看。

**视觉可以慢慢调，IA 错了每天都在收税。** 下面的方案里，第 5 节（IA）和第 7.1 节（值守台）是价值最高的部分。

## 3. 设计方向：运维台，不是仪表盘

八条原则，每条都可证伪、可验收，不是形容词。

**① 例外优先.** 默认视图只显示需要人介入的东西。一切正常时首屏应该几乎是空的，并明确说"一切正常，最近入库 2 小时前"。**首屏面积应与异常数量成正比，而不是与对象总数成正比。**

**② 颜色即信号.** 中性色承载 95% 的界面。饱和色只在状态偏离正常时出现。现在每个枚举都有颜色，代价是"红色"不再意味着"出事了"。

**③ 时间是第一维度.** 备份系统的本质是"周期性事件是否按时发生"。主视图应该是时间轴，不是计数卡片。

**④ 状态三重编码.** 形状 + 文字 + 颜色，缺一不可。值班室的投影仪、夜间的暗光、色觉障碍、灰度打印——任何一种情况下都不能只靠色相判断状态。

**⑤ 渐进披露.** 列表 → 右侧抽屉，不是模态。抽屉保留列表上下文，可以边看详情边扫列表；模态强制你丢掉当前位置。现在 [L63–67](../src/src/BackupMonitor.Api/wwwroot/index.html:63) 的模态承担了本该由抽屉承担的详情展示。

**⑥ 键盘优先.** 命令面板（⌘K）作为一等导航。运维员一天要跳转几十次，鼠标点击是税。

**⑦ 暗色是默认，不是选配.** 值班、夜间、大屏常驻——暗色才是这类系统的主场景。

**⑧ 数字要能扫.** 等宽数字（`tabular-nums`）、单位右对齐、量级缩写统一。一列容量数字如果不对齐，就只能一个一个读。

## 4. 设计令牌

唯一的颜色与字号来源。所有组件只准引用令牌，不准写字面值。

### 4.1 颜色

刻意避开 Tailwind 默认值。中性色系带极轻微的冷偏，避免纯灰的呆板；语义色是重新调过的，不是 `green-600` 那一套。

```css
/* tokens.css */
:root {
  /* ── 中性：承载界面 ───────────────────────────── */
  --ink-0:   #ffffff;
  --ink-50:  #f4f6f8;
  --ink-100: #e6ebee;
  --ink-200: #ccd5da;
  --ink-300: #a7b4bc;
  --ink-400: #7f8f99;
  --ink-500: #5e6d77;
  --ink-600: #46545d;
  --ink-700: #333f47;
  --ink-800: #232d34;
  --ink-900: #161e23;
  --ink-950: #0c1216;

  /* ── 强调：只用于「可交互且需引导」──────────────
     刻意选在语义色相之外（非绿/琥珀/红/蓝），
     这样「这是个按钮」和「这是个状态」永远不会混淆 */
  --accent:       #5b4fc7;
  --accent-hover: #4a3fb0;
  --accent-weak:  #eeecfa;
  --accent-fg:    #ffffff;

  /* ── 语义：只用于状态偏离 ────────────────────── */
  --ok-fg:   #0f7a4a;  --ok-bg:   #e6f4ec;  --ok-bd:   #a8d9be;
  --warn-fg: #96590a;  --warn-bg: #fcf1df;  --warn-bd: #ebc98a;
  --err-fg:  #b3261e;  --err-bg:  #fcebea;  --err-bd:  #f0b4b0;
  --info-fg: #0b5fa5;  --info-bg: #e6f0fa;  --info-bd: #a9cceb;

  /* ── 语义别名（组件只引用这一层）────────────── */
  --bg:            var(--ink-50);
```

### 4.2 排版

```css
:root {
  --font-sans: system-ui, -apple-system, "Segoe UI Variable Text", "Segoe UI",
               "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei UI",
               "Noto Sans SC", sans-serif;
  --font-mono: ui-monospace, "Cascadia Mono", "JetBrains Mono", Consolas,
               "Noto Sans Mono CJK SC", monospace;

  --t-micro: 11px/16px var(--font-sans);   /* 表头、单位、时间戳 */
  --t-sm:    12px/18px var(--font-sans);   /* 徽标、次要信息 */
  --t-body:  13px/20px var(--font-sans);   /* 表格正文、表单 —— 默认 */
  --t-md:    14px/22px var(--font-sans);   /* 段落 */
  --t-lg:    16px/24px var(--font-sans);   /* 区块标题 */
  --t-xl:    20px/28px var(--font-sans);   /* 页标题 */
  --t-num:   28px/32px var(--font-sans);   /* 关键指标 */
}
```

三条硬规则：

- **只用 400 / 500 / 600 三档字重。** 现在 [L53](../src/src/BackupMonitor.Api/wwwroot/index.html:53) 用 700 撑指标数字——字号够大时 600 就足够，700 在中文字体下会糊。
- **所有数字单元格加 `font-variant-numeric: tabular-nums`.** 容量、计数、耗时列必须能竖着扫。这是本次改动里投入产出比最高的一条。
- **ID / 哈希 / 路径 / 主机名一律 `--font-mono`.** 这个系统满屏 GUID 和 SHA256，等宽不是风格选择，是功能需求。

正文从 14px 降到 13px：ops 工具的默认密度应该更高，同屏多看 40% 的行。

### 4.3 间距、圆角、层级、动效

```css
:root {
  --s-1: 4px;  --s-2: 8px;  --s-3: 12px;
  --s-4: 16px; --s-6: 24px; --s-8: 32px; --s-12: 48px;

  --r-sm: 4px;   /* 徽标、输入框 */
  --r-md: 6px;   /* 按钮、卡片 */
  --r-lg: 10px;  /* 抽屉、命令面板 */

  --e-1: 0 1px 2px rgba(12,18,22,.06);          /* 下拉、悬浮行 */
  --e-2: 0 8px 24px -4px rgba(12,18,22,.14);    /* 抽屉、面板 */

  --dur-fast: 120ms;
  --dur-base: 180ms;
  --ease: cubic-bezier(.2, 0, 0, 1);

  --row-h: 32px;          /* 紧凑（默认）*/
}
:root[data-density="comfortable"] { --row-h: 40px; }

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
}
```

动效只用于三件事：状态变化、抽屉/面板进出、Toast。**表格行悬停不做动画**——扫列表时满屏渐变会让人晕。

全部间距落在 4px 栅格上。现在 `6px 9px` `14px 16px` `18px 20px` 这类值是随手写的，没有系统。

## 5. 信息架构重组

12 项扁平导航 → 4 组，并把「待办」提升为一等公民。

| 组 | 项 | 相对现在的变化 |
| --- | --- | --- |
| **值守** | 概览 | 由「仪表盘」重做，见 §7.1 |
| | **待办** | **新增。** 汇总待审批客户端、连续失败任务、待签发恢复、未确认严重告警 |
| | 告警 | 同类折叠 + 批量确认 |
| **机群** | 客户端 | |
| | 备份任务 | |
| **数据** | 备份集 | 新增时间轴视图；恢复入口内嵌 |
| | 恢复 | |
| **管理** | 保留策略 | |
| | 通知 | **合并**「通知设置」+「通知投递」为一页两 Tab——设置是配置，投递是该配置的运行结果 |
| | Agent 升级 | |
| | 作业历史 | 由「批量操作」改造，见下 |
| | 审计日志 | |

两处实质改动，不只是换名字：

**「批量操作」不该是导航项。** 批量预检、批量上传本质是**对一批客户端/任务执行动作**，入口应该在机群列表里（多选行 → 工具条出现批量动作），而不是先跳到一个空页面再回头挑对象。这个页面保留下来的价值是**查看已提交批次的执行结果**，所以改名「作业历史」，放进管理组。

**「待办」是新增的，也是整个 IA 重组的核心。** 现在待审批客户端藏在客户端列表的行内按钮里——你得先想到去那儿看。把所有"等着人做决定"的事项聚到一处，配合原则①，控制台才从"给你看数据"变成"告诉你该做什么"。

导航仍是侧栏，但配合 ⌘K 命令面板后，侧栏可以默认折叠成 56px 图标栏，需要时展开。

## 6. 组件规范

### 6.1 状态标记（替换现有 `.badge`）

现在六种粉彩胶囊，纯色相编码。改为**形状 + 文字 + 色**三重编码：

| 语义 | 标记 | 用于 |
| --- | --- | --- |
| 正常 / 在线 / 已入库 | `●` 实心圆 · 绿 | |
| 进行中 / 上传中 | `◐` 半填充（可旋转） · 蓝 | |
| 待处理 / 待审批 | `○` 空心圆 · 琥珀 | |
| 失败 / 离线 | `▲` 三角 · 红 | 三角形在灰度下也能一眼认出 |
| 已禁用 / 已关闭 | `⊘` · 灰 | |

```css
.status { display:inline-flex; align-items:center; gap:var(--s-2);
          font:var(--t-sm); white-space:nowrap; }
.status::before { font-size:9px; line-height:1; }
.status--ok::before   { content:"●"; color:var(--ok-fg); }
.status--busy::before { content:"◐"; color:var(--info-fg); }
.status--wait::before { content:"○"; color:var(--warn-fg); }
.status--err::before  { content:"▲"; color:var(--err-fg); }
.status--off::before  { content:"⊘"; color:var(--text-faint); }
```

**关键取舍：列表里的状态不再用背景色块。** 一屏 20 行、每行 3 个彩色胶囊，颜色就失去了报警能力。带背景的胶囊只保留给**真正异常**的状态（失败、离线、严重告警），正常状态用符号 + 灰文字。这一条直接兑现原则②。

### 6.2 数据表格

```
行高      32px（紧凑，默认）/ 40px（舒适）
表头      粘性定位，--t-micro，大写字距 +0.04em，不用背景色，用 1px 下边框
斑马纹    不用。用行分隔线（1px --border）
悬停      仅背景微变（--surface-sunk），无过渡动画
选中      左侧 2px --accent 竖条 + --accent-weak 背景
数字列    右对齐 + tabular-nums
时间列    相对时间（"2 小时前"），title 挂绝对时间；超过 7 天显示日期
空态      见 6.5
加载      骨架行（3 行占位），不是"加载中…"
排序      表头可点，aria-sort，箭头指示
```

多选：首列复选框，选中后**工具条原地变形**为批量动作条（显示"已选 5 项"+ 动作按钮），不弹模态。

### 6.3 详情抽屉（替换详情类模态）

```
宽度      520px（普通）/ 720px（含文件树）
位置      右侧滑入，--dur-base
遮罩      rgba(12,18,22,.32)，点击关闭
关闭      Esc / 遮罩 / 右上角 ×
焦点      打开时 focus trap，关闭后焦点归还触发行
内容      顶部标题 + 状态 + 主要动作；下方 Tab 分区
URL       同步到 hash（#/clients/{id}），可直接分享/刷新
```

表单类模态保留（新建任务、创建策略），**详情类一律改抽屉**。区别标准：需要对照列表看的 → 抽屉；需要专注填写的 → 模态。

### 6.4 命令面板（新增）

`⌘K` / `Ctrl+K` 唤起，单一输入框驱动三类结果：

1. **跳转** — 任意页面
2. **搜索** — 客户端主机名 / 任务名 / 备份集编码 / 客户端 ID（走已有的列表接口 `keyword` 参数）
3. **动作** — "审批 web-01"、"给 db-02 下发预检"

配套键位：

| 键 | 动作 |
| --- | --- |
| `⌘K` / `Ctrl+K` | 命令面板 |
| `g` `d` / `g` `c` / `g` `a` | 跳概览 / 客户端 / 告警 |
| `/` | 聚焦当前页搜索框 |
| `j` / `k` | 上下移动选中行 |
| `Enter` | 打开选中行抽屉 |
| `x` | 勾选当前行 |
| `Esc` | 关闭抽屉 / 面板 / 清除选择 |
| `?` | 快捷键一览 |

### 6.5 空态与加载态

现在统一是 `.empty{padding:30px;text-align:center}` + "无数据"。分成三种，各有各的话要说：

| 类型 | 场景 | 内容 |
| --- | --- | --- |
| **首次为空** | 还没有任何客户端 | 说明这是什么 + 主行动按钮（"生成注册令牌"）+ 文档链接 |
| **筛选为空** | 筛选后无结果 | "没有匹配「xxx」的客户端" + 清除筛选 |
| **正常的空** | 没有待办事项 | ✓ + "没有待处理事项" + 上次检查时间。**这是好消息，要说得像好消息** |

加载态一律用骨架屏（灰块占位，形状与真实内容一致），不用文字。骨架不做闪烁动画——ops 界面频繁刷新，闪烁很烦人。

## 7. 逐屏重构

### 7.1 概览 →「值守台」（核心改动）

现状：4 张计数卡 + 服务健康 + 3 个分布列表 + 无坐标轴柱状图。全是库存信息。

重做为四层，**从上到下按"是否需要你行动"排序**：


**② 待办队列**

X = 最近 14 天，Y = 备份任务，一格 = 当天入库状态。**行按异常优先排序**，出问题的任务永远浮在最上面。悬停出详情，点击进任务。

这张图直接回答"昨晚该跑的都跑了吗"——现有 UI 完全回答不了的那个问题。它替换掉那张只能表达"全系统每天入库了几个"的无轴柱状图。

**④ 容量与趋势**

## 8. 可访问性（作为验收项，不是"以后再说"）

- 正文对比度 ≥ 4.5:1，大字与图形元素 ≥ 3:1。§4.1 的令牌在明暗两套下均已按此校准
- **任何状态不得仅靠色相传达**（见 6.1）。自检方法：截图转灰度，仍能区分全部状态
- 焦点环 `2px solid var(--accent)` + `2px offset`，所有可聚焦元素可见。不准 `outline:none`
- 抽屉与命令面板：focus trap、Esc 关闭、关闭后焦点归还触发元素
- 表格用语义化 `<table>` + `<th scope>`，排序列带 `aria-sort`
- 纯图标按钮必须有 `aria-label`
- Toast 用 `role="status"` `aria-live="polite"`；错误用 `role="alert"`
- 尊重 `prefers-reduced-motion`（§4.3 已含）

## 9. 技术选型：保持零构建

**不建议引入 React / Vue / 构建链。**

理由不是保守，是这个项目的约束是真实的：架构书通篇强调「轻量级」，服务端明确不依赖 Node（[doc2.md](../轻量级集中备份采集与监控系统_系统架构书_V1.0.md) 6.1 列出的客户端不依赖项就包含 Docker、Java 等）。当前形态是**一个文件拷进 wwwroot 就能跑**。引入构建链会把部署从"拷文件"变成"装 Node + 构建 + 产物版本管理"，对一个部署在内网 Windows Server 上的轻量系统是净损失。

而且——**"重构 UI 就换个框架"恰恰是最典型的那种 AI 式回答**。这里不需要。

建议：保留原生 JS，但按职责拆成 ES module（浏览器原生支持，仍然零构建）：

```
wwwroot/
  index.html            外壳 + 挂载点 + <script type="module">
  css/tokens.css        §4 全部令牌 —— 唯一的颜色与字号来源
  css/base.css          重置 / 排版 / 表单
  css/components.css    表格 / 状态 / 抽屉 / 命令面板 / 空态 / 骨架
  js/api.js             请求封装 + 令牌刷新 + 错误规范化
  js/ui.js              组件工厂 table() drawer() palette() toast() skeleton()
  js/views/*.js         一视图一文件
```

现在 1200 行 JS 挤在一个 `<script>` 里，视图函数、动作分发、工具函数交织。拆分本身就能解决大半的可维护性问题，且不引入任何工具链。

若将来确实需要（比如要做实时推送 + 复杂状态同步），再上构建也不迟——届时 §4 的令牌层可以原样迁移。

## 10. 分期实施

每期独立可上线，按「风险从低到高、收益从广到深」排序。

| 期 | 内容 | 影响面 | 风险 |
| --- | --- | --- | --- |
| **P1** | 令牌层（§4）+ 暗色 + 排版密度 + tabular-nums | 全站观感立刻改变 | 极低，只改 CSS，不动结构 |
| **P2** | 组件层：表格 / 状态标记 / 抽屉 / 空态 / 骨架（§6） | 所有列表页 | 低，逐组件替换 |
| **P3** | IA 重组（§5）+ 命令面板 + 键盘导航 | 导航与路由 | 中，需同步更新 hash 路由 |
| **P4** | 值守台 + 时序热力图（§7.1） | 首页 | 中，**需后端扩展 task-summary 接口** |
| **P5** | 各列表页逐个迁移到新组件（§7.2–7.5） | 逐页 | 低，可一页一页来 |

**P1 单独上线就值得做**：换掉 Tailwind 默认色板、补上暗色、把数字改成等宽、把正文降到 13px——不动一行结构代码，"AI 味"消掉一大半，因为第 1、7 两条症状是纯 CSS 问题。

**P4 收益最大但依赖最多**，别提前做。

## 11. 验收标准

不用"看起来更现代"这种说法验收。用这七条：

1. **无异常时，概览首屏不超过一屏高**，且明确显示"一切正常"
2. **截图转灰度后，全部状态仍可区分**（验证三重编码）
3. **1080p 下客户端列表首屏可见 ≥ 20 行**（现在约 12 行）
4. **全部核心流程可纯键盘完成**：登录 → 查待办 → 审批客户端 → 查看备份集详情
5. **明暗两套主题对比度全部达标**（axe / Lighthouse 无对比度告警）
6. **首屏 JS < 60KB 未压缩，零外部网络请求**（保持内网可用、无 CDN 依赖）
7. **"昨晚该跑的备份都跑了吗"能在首屏一眼回答**，无需任何跳转

第 7 条是这次重构的根本目的。前六条都达标但第 7 条没做到，就等于只做了美化。
